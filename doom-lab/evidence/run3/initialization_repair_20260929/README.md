# Initialization and native feedback verification

The original v3 scenario wrapper forced `episode_start_time=1`, replacing the Basic configuration's 14 tics and navigation's 10 tics. It also lacked a private per-engine Doom configuration file. Both were corrected before the new bootstrap corpus was admitted. The earlier `baby_bootstrap_*_01` runs remain immutable diagnostics and are excluded from the corrected bootstrap.

The original suspicion that the short Basic demonstrations had identical, uninitialized monsters was **not supported**. On the same 16 seeds, both old and corrected initialization produced 16 distinct initial pixel hashes and 16 distinct visible object layouts. Both navigation configurations produced 16 distinct pixel hashes; the visible-object layout did not vary. Repeating a corrected Basic and navigation seed reproduced the exact initial pixel hash. This check changed start time and configuration isolation together and does not isolate their causal effects.

The corrected source preserves scenario warm-up, gives each engine a temporary `vizdoom.ini`, disables sound/crosshair/automap, fixes HUD/weapon/decals/particles rendering, records configured and observed initial tics, and cleans temporary configuration on initialization failure. Original IWAD tasks retain their explicit one-tic start control.

The native feedback verifier used two actual autonomous contexts from an **untrained** small, depth-three recursive Cadence control, Basic seed `1100200000`, at decisions zero and one. Each of 20 possible first actions executed four native tics, followed by the same frozen qualified actor until a 36-tic total horizon or native terminal. The actual selected action's first native outcome was checked against the experience record; prefix outcomes, current pixels and all four sensory/history ports were also checked exactly (ports with absolute tolerance `1e-12`).

Fresh Actor parsing, one reset immutable Actor, and two spawned workers caching one immutable Actor each produced exactly equal labels, action sequences, and native outcomes, excluding wall-clock measurements. Every branch still created a fresh Doom engine. The verification performed 120 engine initializations, 4,320 branch tics, 240 prefix-replay tics, and 960 qualified continuation queries out of 960 attempts, in 64.67 seconds. Serial cached execution took about 11.4 seconds per 20-action context versus 13.6–14.0 seconds with repeated parsing. Summed worker times are not parallel wall times.

One context's only action contrast concerned native shot penalties; the other was entirely tied. This verifies replay and caching, not useful learning or shooting competence. Native event vectors are preserved separately from target conversion. Tied contexts should not produce an artificial preference. The subsequent learner must declare whether it uses return regression or outcome-derived policy preferences and must not silently combine incompatible target units.

Twenty-one focused tests passed, covering outcome accounting, preserved native warm-up, cleanup after initialization failure, native terminal clock reset and shortened final action, exact replay custody, refusing non-autonomous/fallback records, and whole-context refusal when any continuation is unqualified. Producer scripts are `verify_scenario_start.py` and `verify_native_feedback.py`; complete verification inputs, frozen sources and branch results remain in the corresponding AWS run directories. The local `start_diversity_receipt.json`, `basic02_summary.json`, `navigation02_summary.json`, and `native_feedback_receipt.json` are the compact receipts.
